# Relatório — Marco 2

- **Status:** implementação validada localmente e aprovada para publicação junto ao Marco 3. Nenhuma escrita no banco de produção pelo processo de validação.
- **Escopo:** reduzir XSS nas tabelas administrativas e tornar imprevisíveis os links individuais criados daqui em diante. Nenhum hash já gravado foi alterado ou rotacionado; `/u/:hash` continua atendendo links legados.
- **Alterações:** `get-users.js`, `get-simple-list.js` e `restricoes.js` criam nós DOM e inserem dados de participantes via texto, sem interpolar nomes, nicks ou hashes em HTML. O link individual é montado com `encodeURIComponent` para o segmento do hash. O cadastro em `api/index.js` passa a gerar 32 bytes aleatórios (64 caracteres hexadecimais), em vez do MD5 truncado do nome. A página inicial do painel ganhou acesso à listagem; o botão de copiar aceita cliques no ícone ou no botão, copia a URL exata, tenta um fallback se a Clipboard API falhar e mostra feedback de falha caso não seja possível copiar. A cópia estática `amigo-oculto-back/admin/` foi sincronizada.
- **Verificação:** `npm test` passou **22/22**; novos testes verificam exibição literal de conteúdo com markup malicioso, link codificado, checkbox de restrições, tokens aleatórios distintos para nomes iguais, navegação até a listagem e cópia ao clicar no ícone/botão, incluindo fallback/erro. Os testes de cadastro usam `Pessoa.create` simulado e não acessam banco. O responsável confirmou localmente a exibição literal de nomes/nicks e a criação de links diferentes antes destes ajustes de interface.
- **Limites:** a troca de geração não fortalece os hashes antigos; a rotação deles permanece para a etapa final aprovada pelo responsável, com backup e plano de rollback de produção. A atribuição de IDs por `MAX(id)+1` e as falhas de transação/restrições são problemas separados, ainda pendentes. Sorteio e resultado ausente foram selecionados para o Marco 3; não foram alterados no Marco 2. Os testes DOM usam um substituto mínimo, não um navegador real.
- **Publicação:** o responsável autorizou publicar os Marcos 2 e 3 juntos após backup verificado. Push em `main` aciona deploy automático no Render. Não executar alterações de dados ou rotação de links sem autorização específica.
